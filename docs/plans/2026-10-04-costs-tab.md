# Plan: Costs dashboard tab — provider cost view + `GET /api/cost-series`

**Goal:** Ship the approved `#/costs` tab (period selector, per-provider KPI cards, cost-share donut, daily stacked bars, per-model table) backed by one new read-only endpoint `GET /api/cost-series` with NEW param validation (`fromisoformat`, 400 on invalid / `since >= until`) and its own null-preserving stored-first merge in the handler (unpriceable groups → `cost_usd: null`, not `0`).

**Spec ref:** docs/specs/2026-10-04-costs-tab.md

> Repo constraints that bind every task: stdlib only, SQL parameter binding ALWAYS (`?` for every user-reachable value; f-strings only for fixed internal SQL fragments), files ≤ ~400 lines, tests fully offline (unittest only, explicit temp paths, no env patching), English throughout.
> **Explicitly NOT touched (spec §Files):** `token_dashboard/db.py`, `token_dashboard/scanner.py`, `token_dashboard/opencode_source.py`, `token_dashboard/opencode_v2_source.py`, `cli.py`, `web/charts.js`, and every other `web/routes/*.js`.
> TDD is mandatory for Tasks 1–2 (backend: failing test first, then implement, then verify). Tasks 3–4 are frontend implementation-first — the project has no JS test framework (spec §Design Decisions 7): frontend verification is command-based checks plus **(manual)** browser items. Task 5 is wiring + end-to-end verification.
> Provider logic is frontend-only (spec §Design Decisions 4) — the backend never groups by provider. The handler does its OWN null-preserving merge (spec §Design Decisions 5, user resolution R2): stored cost when `> 0`, else computed; `cost_usd: null` for unpriceable groups — `merge_model_group_cost` is NOT reused (it coerces unpriceable cost to `0`). The frontend consumes ONLY `/api/cost-series` — never `/api/by-model`.
